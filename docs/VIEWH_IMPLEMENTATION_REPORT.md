## 3. Item 10 coverage (multi-horizon prediction)

- One row per target the payload names; one column per horizon from **the payload's own
  `horizons_min` plus the horizons named in its `missing` pairs** — the configured 5/10/15/30 of
  `configs/ml.yaml` arrive through the payload, never hard-coded (no horizon is hard-coded in the
  renderer).
- Per cell: predicted value at `FormatSettings` precision, unit in the row head, `±` ensemble
  spread where Model A reported one (value alone otherwise). **No confidence percentage is derived
  or displayed anywhere** (FR-23, AC-18).
- The `Current` column is the observed value in the OBSERVED channel; every forecast column is
  PREDICTION — both channels badged (`dt-badge--observed` / `dt-badge--prediction`), so the two
  can never be read as one series (item 10's two-channel rule).
- A missing (target, horizon) cell shows `unavailable — no trained Model A for this target at this
  horizon` when the payload's `missing` names the pair, else `unavailable — not carried in this
  prediction payload`. A wholly-missing target gets a row of stated absences (current cell = the
  no-value glyph `—`, never 0) plus the payload's `missing` names in a note.
- `model_version` shown with the grid when present (PRD 13.4).

## 4. Item 11 coverage (anomaly)

The PRD §15 contract, line by line, all values Model B's own:

- `WARNING` banner (alarm styling) for an anomalous row; **NORMAL rows render "No anomaly
  detected."** (the frozen layer's own wording), not a blank card.
- `Detected anomaly: <display_cause>` — where evidence is inconclusive this reads the VERBATIM
  `"Evidence inconclusive"` label, and the nearest regime signature still appears **under its own
  label as a similarity match, never as a cause** (`"Nearest regime signature (similarity match,
  not a cause): …"`, with the payload's cosine when finite).
- `Likely cause (model-based hypothesis): <hypothesis>` — VERBATIM label from the payload.
- `Affected variables: <ranked list>` — each entry `tag (direction, z=+x.x)`, the frozen
  `AnomalyReport.render()` presentation; empty list shows the frozen layer's own
  `"none above the control limits"`, never a blank line.
- `Suggested action (rule-based suggestion, not a diagnosis): <action>` — VERBATIM label.
- The PRD §17 view-7 "live anomaly score" is the payload's own number; `out_of_distribution`
  earns its own pill when true.

## 5. Missing / degraded-data behavior

| State | Rendering |
|---|---|
| `PredictionSet.unavailable` (capability gate, model refusal with NaN row / short window, no rows simulated) | `MODEL_UNAVAILABLE_LABEL` card with the model's own `unavailable_reason`; no numbers |
| Available but no forecasts | stated ("carries no forecasts"), no substitute grid |
| Missing single (target, horizon) | `unavailable — <reason>` cell (see §3) |
| Wholly-missing target | row of stated absences, current cell `—` |
| `AnomalyState.unavailable` | `MODEL_UNAVAILABLE_LABEL` card + reason; no anomaly manufactured |
| Normal verdict | "No anomaly detected." card with score |
| Inconclusive evidence | §4 above |
| Degraded capabilities (`caps.predictions` / `caps.anomaly` false) | `DashboardState.intelligence()` already builds the unavailable states; the renderer displays them as above |
